Part 1 - Tuning the Model Structure¶

Similar to random forests, there are two categories of hyperparameters we are concerned with:

  1. Those impacting the base learners directly (max depth, etc.)
  2. Those impacting how the base learners are incorporated into the ensemble (namely the learning rate and number of iterations).

The most commonly tuned hyperparameters for the base learners, roughly in their order of importance are:

  • max_depth - controls the complexity of individual trees by restricting their maximum depth.
  • min_child_weight - controls how readily a tree is allowed to create additional splits by requiring a minimum amount of data (technically, weighted observations) within a node for it to be partitioned. Larger values produce simpler trees and can help reduce overfitting.
  • subsample - promotes variety among trees and helps prevent overfitting by randomly selecting a fraction of the training observations to be used when building each tree.
  • colsample_bytree - promotes variety among trees and helps prevent overfitting by randomly selecting a fraction of the available predictors that may be used when constructing each tree.

Less widely used, but potentially useful hyperparameters are reg_alpha and reg_lambda:

  • reg_alpha (L1 regularization) encourages some tree contributions to become exactly zero. Larger values create a simpler model and can be useful when many predictors contain little useful information.
  • reg_lambda (L2 regularization) shrinks tree contributions toward zero without forcing them to be exactly zero. Larger values generally produce a smoother, more conservative model that is less likely to overfit the training data.

Standard practice is to first find a configuration for the base learners that works adequately well, then to find a learning rate that is not too aggressive or too slow, then use early stopping to determine the effective number of boosting iterations.

The xgboost library is designed for compatibility with many functions from sklearn, including pipelines and cross-validated searches:

Part 2 - Learning Rates and Early Stopping¶

To properly determine the ensemble-level hyperparameters (learning rate and number of iterations) we'll need to split off part of the training data to use as a validation set. We can then have xgboost check the performance of the current ensemble on the validation set every fixed number of boosting iterations. The example below monitors the AUC across boosting iterations, stopping after the validation metric has failed to improve for 30 consecutive boosting iterations.

In [13]:
from sklearn.model_selection import train_test_split
import xgboost as xgb

## Create validation set
xgb_train_X, val_X, xgb_train_y, val_y = train_test_split(train_X,train_y,test_size=0.25,random_state=0)

## Start with best structure from Part 1
model2 = rand_res.best_estimator_

## Update parameters to include early stopping, and a trial learning rate with a large number of estimators
model2.set_params(early_stopping_rounds=30, learning_rate=0.03, n_estimators=5000, eval_metric="auc")

## Fit model
model2.fit(xgb_train_X, xgb_train_y, eval_set=[(xgb_train_X, xgb_train_y),(val_X, val_y)],verbose=False)
print(model2.best_iteration)
print(model2.best_score)

Part 3 - Evaluation Metrics¶

Our previous examples have used AUC as the evaluation metric without much additional consideration. However, from a model building perspective it is often useful to rely upon log-loss (also called cross-entropy loss) to tune the learning rate due to its greater sensitivity to small improvements in predicted probabilities.

$$ \text{log-loss} =-\frac{1}{n}\sum_{i=1}^{n} \left[y_i \log(\hat p_i) + (1-y_i)\log(1-\hat p_i) \right] $$

where:

  • $y_i \in \{0,1\}$ is the true class label
  • $\hat p_i$ is the predicted probability of the positive class

Unlike classification accuracy or AUC, log-loss rewards models for producing probabilities that are both correct and confident, while heavily penalizing confident mistakes. Learning curves that use log-loss tend to be smoother and more reliable, making it the most common evaluation metric for early stopping even if it is not the final evaluation metric for the application.

Consider the following learning curves:

In [10]:
## log-loss
model2.set_params(learning_rate=0.05,n_estimators=5000,early_stopping_rounds=30,eval_metric="logloss")
model2.fit(xgb_train_X, xgb_train_y,eval_set=[(val_X, val_y)],verbose=False)
