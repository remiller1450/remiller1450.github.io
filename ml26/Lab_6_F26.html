Lab 6 - Feature Engineering and Ensemble Models¶

Up until this point we've applied machine learning models to "tabular data", or 2-dimensional data objects that have a spreadsheet-like format, where each row represents a single observation, and each column represents a predictive feature. However, many modern data collection protocols do not innately produce tabular data, for example:

  • Social media and news publishers produce textual data, where each observation is a sequence of words or characters.
  • Wearable devices and other sensors produce time-series data, where each observation consists of many time-ordered measurements, often spanning multiple channels.
  • Medical technologies and satellites produce image data, where each observation consists of spatially structured pixel intensities.
  • Audio recording devices produce audio wave data, which can often be viewed as a specialized form of time-series data.

None of these data types can be used directly by the types of models we've encountered so far in the course (we'll talk about deep learning models soon), which raises an important question:

How can we create effective representations of raw data so that it can be used by machine learning models?

The answer to this question is feature engineering, the process of using domain expertise to create meaningful predictive features that can be used by models designed for tabular data.

Part 1 - Feature Engineering and Textual Data¶

The "clickbait" data set given below contains $n=3000$ news article headlines from "clickbait publishers", including Upworthy, Buzzfeed, Thatscoop, ViralNova, Scoopwhoop, and ViralStories, and $n=3000$ headlines from websites deemed not to publish clickbait, including The New York Times, WikiNews, The Guardian, and The Hindu.

In [2]:
clickbait = pd.read_csv("https://remiller1450.github.io/data/clickbait_headlines.csv", encoding='latin-1')

Our goal is to develop a model that can predict whether an article comes from a clickbait publisher (Label = 1) based upon the article's headline.

There are three broad approaches to engineering useful features:

  1. Domain expertise - we might know from experience that clickbait headlines frequently start with a number (ie: "15 Things You'll Only Understand If..."), so we might create a binary feature indicating whether or not a headline begins with a number.
  2. Pattern discovery - we might graph the frequencies of the top $k$ words that appear in clickbait and non-clickbait headlines, then based upon these differences we could create a clickbait keyword score for each headline.
  3. Automated extraction - we might generate a Term Frequency-Inverse Document Frequency (TF-IDF) for each word appearing in the data, then use these scores as features.

This lab will focus on the first two approaches, but the third is something I'd encourage you to explore on the course project.

def first_word_q(input_text):
    first_word = input_text.str.split(' ').str[0]
    return 1*((first_word == "What") | (first_word == "Which") | (first_word == "Would") | (first_word == "How") | (first_word == "Can") | (first_word == "Are"))

Part 2 - Feature Engineering and Time-Series Data¶

This part of the lab provides a second example of feature engineering, this time using time-series data collected by an accelerometer worn by $n=15$ subjects as they performed 7 different types of activities.

The data were recorded at 52 Hz, meaning that 52 measurements are present for every second of time recorded by the accelerometer recorded. Our analysis will focus on predicting a subject's activity using 10-second samples of accelerometer data, which are delineated by the variable Sample_Num.

When working with time-series data, we're generally looking to engineer features that capture one of the following characteristics:

  1. The typical values of the signal (mean, median, percentiles, etc.)
  2. The amount of variation in the signal (standard deviation, range, etc.)
  3. The shape or behavior of the signal over time (number of peaks, rates of change, etc.)

For these data, we can clearly observe:

  1. Working tends to have higher average values, particularly along the X and Z axes.
  2. Working tends to have lower amounts of variability in the accelerometer's measurements (aside from some unusual behavior at the very beginning of the series)

Representing these patterns in a tabular dataset can be done using grouped summarization (first introduced in Lab 1!):

Part 3 - Random Forests¶

Recall that a random forest is an ensemble model that combines predictions from many decision trees. By training each tree on a different bootstrapped sample of the data and randomly restricting which features can be considered at each split, random forests often achieve better predictive performance and generalize better than a single decision tree.

A unique aspect of random forests are that they naturally exclude some observations from the training set used by each tree. Bootstrapping will include multiple of some observations, while others will not be sampled. The data-points that were excluded during bootstrapping can be used to calculate "out-of-bag performance" (sometimes abbreviated OOB), which can be interpreted similarly to cross-validated measures of performance.

The existence of OOB performance estimates, combined with the fact that adding more trees will not harm performance, alters how we should approach hyperparameter tuning. In general our workflow will be:

  1. Track OOB performance by n_estimators using default values for all other hyperparameters - the goal is to determine how many trees appear to be enough for performance to stabilize. While there's no guarantee that this will be optimal for all other hyperparameter configurations, it will most likely provide a reasonable value.
  2. Tune the other main hyperparameters: max_features, max_depth, min_samples_leaf using a cross-validated grid search search (or random search) using the n_estimators chosen in step 1.
  3. Plot the OOB learning curve for the final configuration of max_features, max_depth, min_samples_leaf to confirm enough trees were used.

Shown below is a template that plots the OOB performance for n_estimators going from 20 to 600 by increments of 20. Note that the argument warm_start=True greatly improves computational efficiency, as new trees are added to the existing forest (rather than recreating the entire forest from scratch each time we call rf.fit()).

In [14]:
from sklearn.ensemble import RandomForestClassifier
rf = RandomForestClassifier(n_estimators=1, warm_start=True, oob_score=True, random_state=0)

n_trees = []
oob_acc = []

## Increment the number of base learners, tracking OOB accuracy 
for n in range(20, 600, 20):
    rf.n_estimators = n
    rf.fit(train_X_FE, train_act_y)

    n_trees.append(n)
    oob_acc.append(rf.oob_score_)

plt.plot(n_trees, oob_acc, marker='o')
plt.xlabel("Number of Trees")
plt.ylabel("OOB Accuracy")
plt.title("Random Forest OOB Learning Curve")
plt.show()
